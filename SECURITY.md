# Security Policy

## Supported Versions

We release patches for security vulnerabilities in the following versions. Older versions
are not supported and will not receive updates.

| Version | Supported          |
| ------- | ------------------ |
| 1.x.x   | :white_check_mark:  |

**Note:** As PayLock Core is currently in its MVP stage, only the latest release version
receives security updates. If you are using an older commit, please upgrade immediately.

## Reporting a Vulnerability

We take the security of PayLock Core seriously. If you believe you have found a
security vulnerability, **please do not report it publicly** on issues or discussions.

Instead, please send a detailed report to our security team directly at:

**📧 Email:** [uniqueteamyemen@gmail.com](mailto:uniqueteamyemen@gmail.com)

Please include the following details in your report:
- A clear description of the vulnerability.
- Steps to reproduce the issue, including any relevant code or configuration.
- The potential impact of the vulnerability.
- Any possible mitigations you have identified.

### What to Expect

- **Acknowledgment:** You will receive an acknowledgment of your report within **48 hours**.
- **Assessment:** Our team will investigate and assess the validity and severity of the report.
- **Communication:** We will keep you informed of our progress and intend to provide a resolution timeline within **5 business days**.
- **Disclosure:** We follow a coordinated disclosure process. Once a fix is available, we will publish a security advisory and give credit to the reporter (if you wish).

## Our Commitment

We are committed to working with security researchers to verify and address any potential
vulnerabilities reported to us. We ask that you give us reasonable time to investigate
and mitigate any issues before public disclosure.

Thank you for helping keep the PayLock protocol and its users safe.
